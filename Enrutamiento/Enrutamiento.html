    Enrutamiento IPv4¶

    El enrutamiento es el proceso mediante el cual se determina la mejor ruta que deben seguir los paquetes de datos para llegar desde un origen a un destino en una red IP. En redes IPv4, este proceso es fundamental para la interconexión de redes y para el funcionamiento de Internet.

    Tipos de enrutamiento¶

    Estático¶

    • Configurado manualmente por el administrador de red.
    • Útil en redes pequeñas o topologías sencillas.
    • Ventajas:
      • Bajo consumo de recursos.
      • Mayor control sobre las rutas.
    • Inconvenientes:
      • No se adapta automáticamente a cambios en la red.
      • Escalabilidad limitada.

    Dinámico¶

    • Utiliza protocolos de enrutamiento para intercambiar información de rutas entre routers.
    • Se adapta automáticamente a cambios en la topología.
    • Protocolos más comunes:
      • RIP (Routing Information Protocol): basado en distancia (nº de saltos).
      • OSPF (Open Shortest Path First): basado en el coste (estado de enlace).
      • EIGRP (Enhanced Interior Gateway Routing Protocol): híbrido (propietario de Cisco).
      • BGP (Border Gateway Protocol): utilizado entre sistemas autónomos (routing interdomain).

    Tabla de enrutamiento¶

    • Estructura que contiene las rutas conocidas por un router.
    • Cada entrada incluye:
      • Dirección de red destino.
      • Máscara de subred.
      • Dirección del siguiente salto (next hop).
      • Interfaz de salida.
      • Métrica (coste asociado a la ruta).

    Proceso de enrutamiento¶

    1. El router recibe un paquete IP.
    2. Consulta la tabla de enrutamiento.
    3. Selecciona la mejor ruta (longitud de prefijo más específica).
    4. Reenvía el paquete a través de la interfaz correspondiente.

    Enrutamiento por defecto (default route)¶

    • Ruta utilizada cuando no hay coincidencia más específica en la tabla.
    • Se configura con la red 0.0.0.0/0.
    ip route add default via 192.168.1.1

    Protocolos de enrutamiento interior y exterior¶

    Tipo Protocolos Ámbito
    IGP (Interior Gateway Protocol) RIP, OSPF, EIGRP Dentro de un sistema autónomo
    EGP (Exterior Gateway Protocol) BGP Entre sistemas autónomos

    Comandos básicos (Linux)¶

    Mostrar tabla de enrutamiento¶

    ip route show

# Mostrar tabla de enrutamiento
ip route show

# Añadir ruta estática
ip route add 192.168.2.0/24 via 192.168.1.1 dev eth0

# Eliminar ruta
ip route del 192.168.2.0/24

    Tabla de rutas estáticas¶

    Red destino Máscara Siguiente Salto Interfaz
    192.168.30.0 255.255.255.0 * (Directo) G0/1: 192.168.30.1
    10.0.0.0 255.255.255.0 * (Directo) S0/0/0: 10.0.0.2
    172.16.0.0 255.255.255.0 10.0.0.1 S0/0/0: 10.0.0.2
    192.168.10.0 255.255.255.0 10.0.0.1 S0/0/0: 10.0.0.2
    192.168.20.0 255.255.255.0 10.0.0.1 S0/0/0: 10.0.0.2
    0.0.0.0 0.0.0.0 10.0.0.1 S0/0/0: 10.0.0.2

    En este caso, Router3 tiene conexión directa con las redes 192.168.30.0/24 y 10.0.0.0/24. El resto de redes se alcanzan a través del salto siguiente 10.0.0.1, correspondiente a la interfaz de Router2.

    Enrutamiento dinámico¶

    Si Router3 usara un protocolo de enrutamiento dinámico como OSPF o EIGRP, y las redes estuvieran bien anunciadas, la tabla se generaría automáticamente. Aun así, con OSPF podríamos ver una tabla similar a:

    Tabla de enrutamiento de Router3 (OSPF):

    Red destino Máscara Tipo Siguiente Métrica
    192.168.30.0 255.255.255.0 Directo * 0
    10.0.0.0 255.255.255.0 Directo * 0
    172.16.0.0 255.255.255.0 OSPF (IA) 10.0.0.1 10
    192.168.10.0 255.255.255.0 OSPF (IA) 10.0.0.1 10
    192.168.20.0 255.255.255.0 OSPF (IA) 10.0.0.1 10
    0.0.0.0 0.0.0.0 OSPF (E2) 10.0.0.1 20

    NOTA

    Como se observa, al usar OSPF el router ya no necesita introducir rutas manuales. Además, la métrica (coste) es calculada automáticamente por el protocolo en función del ancho de banda de los enlaces.

    Conclusión¶

    • Con enrutamiento estático, Router3 requiere todas las rutas de forma explícita.
    • Con enrutamiento dinámico, el router puede construir su tabla automáticamente, facilitando la escalabilidad.
    • En ambos casos, es importante tener al menos una ruta por defecto (0.0.0.0/0) para garantizar salida a Internet o redes desconocidas.
